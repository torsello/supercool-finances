  ⎿  I found no Critical or High defects. The branch adds observability and error reporting only; no money, transaction or idempotency code changed except where logFailure hands a 500 to the reporter. There are five follow-ups: one Medium and four Low.

     1. Medium: the SEC-AC46 test doesn't test what the AC says, and the reporter relies on the transport to free its slots
     - Where: test/unit/platform/error-reporter.test.ts:25-41 and :101-124; src/platform/error-reporting/reporter.ts:111-119.
     - What is wrong:
       - The AC's fake transport "never answers". The test's transport rejects as soon as the abort signal fires, so it does answer.
       - The ShutdownCoordinator in the test has no reporter attached at all. "The shutdown never waits for the reporter" is therefore true by construction and proves nothing about the real wiring.
       - In the code, report() only aborts the signal at 2000 ms. The slot is released only when transport.send settles.
     - How to trigger: use any transport that ignores the abort signal, as the AC describes. After 20 reports, pending stays at 20 for ever and every later report is dropped. Node's fetch does reject on abort, so production is fine today.
     - Impact: SEC-R54's "abandoned after 2000 ms" and SEC-R55 rest on a property no test checks.
     - Suggested fix:
       - When the 2000 ms timer fires, release the slot and record the timeout in the reporter itself, with a guard so a late answer is not counted twice.
       - Rewrite the fake so it ignores the signal.
       - Prove SEC-R55 through the real composition (buildApp plus the coordinator main.ts builds), not a coordinator built without the reporter.
     - AC: SEC-AC46 (SEC-R54, SEC-R55).

     2. Low: lines of a multi-line error message can be sent as stack frames, unscrubbed
     - Where: src/platform/error-reporting/event.ts:132-147. Line 135 skips only the first line of the stack.
     - What is wrong: a V8 stack starts with ${name}: ${message}. If the message has several lines, all of them after the first stay in stack. Any of those lines that looks like a frame is sent as function and filename, and neither field is scrubbed.
     - How to trigger: throw an error whose message is "x\n    at 4321 0192f0a0-0000-7000-8000-00000000a001 (k-77:1:2)". The event then holds the frame {function: "4321 0192f0a0-…", filename: "k-77"}.
     - Impact: this gets around the SEC-R53 scrub. It's unlikely with today's errors (pg's messages are one line).
     - Suggested fix: skip message.split('\n').length header lines instead of one, or build frames from structured call sites (Error.prepareStackTrace). Running scrubMessage over function and filename would also cover it.
     - AC: SEC-AC43 (SEC-R53).

     3. Low: SENTRY_DSN accepts an empty query, an empty fragment and an empty password
     - Where: src/platform/error-reporting/dsn.ts:32-39.
     - What is wrong: the URL parser returns '' for search, hash and password when the ?, # or : is present but empty. So these all pass, though section 1.2 says "no password, query or fragment":
       - https://pk@errors.example/42?
       - https://pk@errors.example/42#
       - https://pk:@errors.example/42

       I checked this with node -e.
     - How to trigger: load the configuration with any of those values.
     - Impact: none in practice, because the envelope URL drops all three. It is still a deviation from the spec's rule.
     - Suggested fix: also reject a raw value that contains ? or #, or a : in the user part before @, and add these three cases to the SEC-AC40 test.
     - AC: SEC-AC40 (SEC-R39).

     4. Low: integration tests depend on timing
     - Where: test/integration/security/error-reporting-unavailable.test.ts:43, :55, :61, :64-66; test/integration/security/error-reporting.test.ts:127.
     - What is wrong:
       - Fixed sleeps of 300 ms and 2300 ms wait for log lines and for the abort.
       - fake.accepted() has length 2 only if the check runs within 5 s of the 4th envelope, which the fake holds for 5 s. Once that hold ends, the 4th counts as accepted too.
       - SEC-AC41 expects ['err-1','err-2'] in the order the envelopes arrive.
     - How to trigger: run on a slow or loaded CI runner. If the gap passes 5 s, accepted() returns 3.
     - Impact: flaky failures.
     - Suggested fix: poll for the expected log line or for pending === 0 (waitUntil); hold the fake for something like 60 s (it is closed in finally); compare request ids as a sorted list.
     - AC: SEC-AC45, SEC-AC41.

     5. Low: plan 007 contradicts the spec on http:// DSNs
     - Where: specs/007-security-ops/plan.md:146.
     - What is wrong: the plan says http:// is accepted "outside production". Section 1.2, SEC-AC40 and dsn.ts all accept a loopback http:// DSN even with NODE_ENV set to production.
     - Impact: misleading documentation.
     - Suggested fix: change it to "for a loopback host, whatever NODE_ENV".
     - AC: missing AC (docs drift).
