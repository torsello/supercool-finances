  rules, plus the commit attribution. Python parses it as valid JSON with those
  counts. I left .claude/settings.local.json alone.

  What the rules protect:
  1. Allow: checks, tests, docker compose and read-only git commands run without
     prompting.
  2. Ask: pushing and changing dependencies always need your approval, which
     keeps the "no new dependency without an ADR or approval" rule.
  3. Deny: blocks history rewrites (force push, +refspec, reset --hard),
     skipping hooks (--no-verify, -n), mass deletion (rm -rf, git clean -f),
     real cloud changes (terraform apply/destroy) and reading .env.

  These rules match the text of a command, not what it does, so they are
  guardrails for an AI assistant, not a security boundary. A different spelling
  gets past them, for example git -C . push --force, bash -c "…" or cat .env.

  quality matters most.                                                         
  Body: the reviewer is a senior engineer for a financial balance service who   
  did not write this code and has not seen the conversation; its job is to find 
  defects, not to praise; it never modifies a file. It inspects files with the  
  Read, Grep and Glob tools, and runs git only as single read-only commands     
  (git status, git diff, git log, git show), never chained with && or | and     
  never with git -C, because the working directory is already the repository

  scope: $ARGUMENTS" (empty means everything changed since the last push, plus  
  uncommitted and untracked files). Then inject the repository state with these 
  two lines, exactly as written, each on its own line (the fallbacks matter: a  
  failing injected command aborts the whole skill):                             
  !`git status --short --branch`                                                
  !`git diff --stat @{upstream} 2>/dev/null || echo "(nothing pushed yet)"`     
  Method: read AGENTS.md and the related specs and ADRs; read every changed     
  file in full, not only the diff; check in this order:                         
  (1) spec conformance: each touched AC is implemented and has a test whose     
  name contains its ID; no behaviour exists that no spec describes;             
  (2) money: no number or float on amounts; bigint in the domain, digit strings 
  at the API, currency exponent respected;                                      
  (3) transactions and concurrency: one database transaction per movement;      
  customer accounts locked one by one in ascending id order; system accounts    
  never locked; checks after locks; nothing awaited outside the transaction     
  that belongs inside it; bounded retries on 40001 and 40P01; no in-process     
  state;                                                                        
  (4) idempotency, as specs 003 and 005 define it: the key row is the first     
  write; a replay returns the stored status and body; a different body is 422;  
  business rejections are stored; unexpected errors are not; the idempotency    
  wait timeout answers 409 and the account lock timeout answers 503, as         
  separate settings;                                                            
  (5) security: authorization on the source account, roles, 404 for foreign     
  resources, strict input validation, no secrets or tokens in logs or committed 
  files, parameterized SQL only;                                                
  (6) failure handling: timeouts ordered database < service < load balancer,    
  pool sizing, graceful shutdown, errors as problem+json;                       
  (7) tests: they assert the invariants, not only the happy path; no sleeps or  
  timing assumptions that make them flaky;                                      
  (8) docs drift: specs, ADRs, OpenAPI, runbooks or README contradicting the    
  code.                                                                         
  Output: findings numbered and ordered by severity (Critical, High, Medium,    
  Low), each with file:line, what is wrong, how to trigger it, impact,          
  suggested fix, and the AC ID it violates (or "missing AC"); one line for each 
  category without findings; a final line "Verdict: ready to ship" or
