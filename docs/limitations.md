# Limitations

What this service does not do, and why, taken from the specs, the ADRs and the deployment notes. Each item links to its source. Where the source gives no reason, none is given here.

The challenge asks for quality over quantity, says a real database and authentication service may be simulated, and says the service need not be deployed to a cloud, only explained with some infrastructure as code ([docs/challenge.md](challenge.md)). Many of the items below follow from that.

The architecture is drawn in the README: the [system context](../README.md#system-context), the [local stack](../README.md#local-stack), the [request lifecycle](../README.md#request-lifecycle), the [data model](../README.md#data-model) and the [AWS deployment](../README.md#deployment-to-aws).

| Audit records through the API                    | Audit records are written but cannot be read or searched through the API. ## Events and integration

The service publishes no domain events and has no outbox.

| Item                      | Why                                                                                                                                                                                                           | Source                                                                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No outbox, saga or 2PC    | A movement is one PostgreSQL transaction across accounts, ledger, idempotency and audit, so it needs no saga, outbox or two-phase commit.                                                                     | [ADR-0002](adr/0002-modular-monolith.md#considered-options)                                                                                                                                                    |
| No external calls         | The service calls no external system, so the key and the movement commit in one transaction. A future call to an external system needs a new ADR moving to two-phase keys (claim, commit, execute, complete). | [ADR-0009](adr/0009-idempotency-inside-the-movements-transaction.md#decision), [consequences](adr/0009-idempotency-inside-the-movements-transaction.md#negative--costs)                                        |
| No event sourcing or CQRS | The append-only ledger already gives an immutable history at a fraction of the complexity. Customer and operator history is a projection of the ledger.                                                       | [ADR-0003](adr/0003-hexagonal-architecture-with-tactical-ddd.md#decision), [ADR-0006](adr/0006-double-entry-ledger-with-signed-integer-minor-units.md#positive), [planning](ai/00-planning.md#what-i-rejected) |
| No independent deploys    | Every release ships every module. If a module is ever split out, a new ADR must first say how its writes stay atomic with the ledger.                                                                         | [ADR-0002](adr/0002-modular-monolith.md#consequences)                                                                                                                                                          |

## Identity and edge security

| Limitation                       | What the source says                                                                                                                                                                                                          | Source                                                                                                                                                             |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Simulated authentication         | HS256 tokens signed with `JWT_SECRET`; no OpenID Connect provider, asymmetric signatures or JWKS. The challenge allows simulating the authentication service. The production design is recorded in ADR-0012.                  | [Spec 006 section 6](../specs/006-auth/spec.md#6-out-of-scope), [ADR-0012](adr/0012-simulated-authentication-with-jwt-and-two-roles.md), [challenge](challenge.md) |
| No login, refresh or revocation  | No login, registration, passwords, MFA or refresh tokens. A token lives at most 15 minutes and cannot be revoked before it expires.                                                                                           | [Spec 006 section 6](../specs/006-auth/spec.md#6-out-of-scope)                                                                                                     |
| One signing secret               | `JWT_SECRET` is a master key: whoever has it can act as any user. It cannot be rotated without a restart, and only one secret is accepted at a time.                                                                          | [ADR-0012](adr/0012-simulated-authentication-with-jwt-and-two-roles.md#negative--costs), [spec 006 section 6](../specs/006-auth/spec.md#6-out-of-scope)            |
| Two roles only                   | No scopes or permissions beyond `customer` and `operator`.                                                                                                                                                                    | [Spec 006 section 6](../specs/006-auth/spec.md#6-out-of-scope)                                                                                                     |
| Timing side channels             | Not addressed for token verification and the ownership check. A transfer to an existing destination may answer more slowly; accepted, because refusing instead would reject a valid transfer and timing leaks the same thing. | [Spec 006 section 6](../specs/006-auth/spec.md#6-out-of-scope), [spec 003 section 6](../specs/003-money-movements/spec.md#6-out-of-scope)                          |
| Rate-limit gaps                  | Clients can burst up to twice the per-user limit around a window boundary; while Redis is down only the edge limit protects the service. No limits per endpoint, account or amount, and no daily quotas.                      | [ADR-0013](adr/0013-rate-limiting-at-the-edge-and-in-redis.md#negative--costs), [spec 007 section 6](../specs/007-security-ops/spec.md#6-out-of-scope)             |
| WAF's 429 is not problem details | WAF cannot add a `requestId` or send `application/problem+json`, so its 429 body is `application/json`; the managed rule groups answer a plain 403.                                                                           | [Spec 007 section 1.6](../specs/007-security-ops/spec.md#16-rate-limits)                                                                                           |
| TLS, mTLS and DDoS               | Local traffic is plain HTTP; TLS ends at the load balancer in AWS. No mTLS between the load balancer and the replicas, and no volumetric DDoS protection beyond the per-IP limit.                                             | [Spec 007 section 6](../specs/007-security-ops/spec.md#6-out-of-scope)                                                                                             |

## Data, consistency and scale

| Limitation                      | What the source says                                                                                                                                                                                                              | Source                                                                                                                                                                                                                                          |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One database primary            | Database write capacity bounds the whole service; throughput is bounded by one PostgreSQL primary and row-lock contention.                                                                                                        | [ADR-0002](adr/0002-modular-monolith.md#negative--costs), [ADR-0005](adr/0005-postgresql-as-the-only-source-of-truth.md#negative--costs)                                                                                                        |
| Hot accounts                    | A hot account processes one movement at a time; its latency grows with its queue.                                                                                                                                                 | [ADR-0008](adr/0008-read-committed-with-ordered-pessimistic-row-locks.md#negative--costs)                                                                                                                                                       |
| The ledger grows forever        | No balance snapshots, archiving or partitioning. Reading a settlement balance is an aggregate query that slows as the ledger grows.                                                                                               | [Spec 002 section 6](../specs/002-ledger/spec.md#6-out-of-scope), [ADR-0006](adr/0006-double-entry-ledger-with-signed-integer-minor-units.md#negative--costs), [ADR-0007](adr/0007-system-accounts-without-a-cached-balance.md#negative--costs) |
| Multixact cost not reported     | Concurrent `FOR KEY SHARE` locks on settlement rows add multixact overhead. ADR-0007's follow-up asks for its measured cost in `docs/performance.md`, which does not report it.                                                   | [ADR-0007](adr/0007-system-accounts-without-a-cached-balance.md#follow-ups), [performance](performance.md)                                                                                                                                      |
| Reconciliation only reports     | It never writes: a repair is a compensating transaction decided by a person. It has no HTTP endpoint and is not scheduled in production.                                                                                          | [Spec 002 section 6](../specs/002-ledger/spec.md#6-out-of-scope)                                                                                                                                                                                |
| Idempotency window              | A request retried after `IDEMPOTENCY_KEY_TTL_SECONDS` runs again, and duplicates sent with different keys are not detected.                                                                                                       | [Spec 005 section 6](../specs/005-idempotency/spec.md#6-out-of-scope), [ADR-0009](adr/0009-idempotency-inside-the-movements-transaction.md#negative--costs)                                                                                     |
| Unknown outcome at the deadline | A request whose `COMMIT` was already sent at the request timeout has an outcome unknown to the client; without a key, a retry may repeat it. A timed-out statement may hold its locks and connection for up to 5 s after the 503. | [ADR-0022](adr/0022-request-timeout-answer-first-then-roll-back.md#negative--costs)                                                                                                                                                             |
| No page numbers or totals       | Keyset pagination gives none, and rotating `CURSOR_SECRET` invalidates every cursor in flight.                                                                                                                                    | [ADR-0017](adr/0017-keyset-pagination-with-signed-cursors.md#negative--costs)                                                                                                                                                                   |

## Operations and observability

| Limitation                                  | What the source says                                                                                                                                                                                                                                                                                                                                                                                               | Source                                                                                                                                                                                                                      |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No reconcile task in AWS                    | `npm run reconcile` runs locally and in CI only. The runtime image ships neither npm nor the script, and no security group admits an operator's host to the database.                                                                                                                                                                                                                                              | [AWS limitations](deployment/aws.md#limitations-and-follow-ups)                                                                                                                                                             |
| No metrics scraping in AWS                  | `METRICS_PORT` is admitted by no security group; the alarms use the metrics AWS publishes.                                                                                                                                                                                                                                                                                                                         | [AWS observability](deployment/aws.md#observability), [spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope)                                                                                                  |
| No error reporting in AWS                   | The tasks have no outbound internet path, so the Terraform sets no `SENTRY_DSN`.                                                                                                                                                                                                                                                                                                                                   | [Spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope), [spec 007 section 6](../specs/007-security-ops/spec.md#6-out-of-scope), [ADR-0023](adr/0023-optional-observability-off-by-default.md#negative--costs) |
| No alerts beyond the AWS alarms, no tracing | The CloudWatch alarms of section 1.8 of spec 008 are the only deployed alerts; the alerts on the service's own metrics and logs are documented with their runbooks but not deployed, and the local Prometheus has no alert rules. Logs reach CloudWatch Logs in AWS and go nowhere else. The correlation id is the only cross-layer identifier; there is no OpenTelemetry tracing, profiling or product analytics. | [Spec 007 section 6](../specs/007-security-ops/spec.md#6-out-of-scope), [alerts without an alarm](observability.md#alerts-without-an-alarm)                                                                                 |
| Local observability is ephemeral            | Prometheus keeps its data inside the container for 1 day; no alert rules, Loki or Tempo locally.                                                                                                                                                                                                                                                                                                                   | [Spec 008 section 1.9](../specs/008-deployment/spec.md#19-observability-profile), [spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope)                                                                      |
| No hot reload                               | A configuration change takes effect on restart.                                                                                                                                                                                                                                                                                                                                                                    | [Spec 007 section 6](../specs/007-security-ops/spec.md#6-out-of-scope)                                                                                                                                                      |
| Documentation checks                        | `npm run docs:check` checks only relative links, because a link to another site can break without a commit.                                                                                                                                                                                                                                                                                                        | [Spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope)                                                                                                                                                        |

| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

The challenge does not require a cloud deployment.                                                                                                | [ADR-0015](adr/0015-terraform-for-infrastructure-as-code.md#negative--costs), [challenge](challenge.md)                                                                                                                             |

| Kubernetes                     | Not supported; Docker Compose locally and ECS in AWS only.                                                                                                                                                                                               | [Spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope)                                                                                                                                                                |
| Contract steps tracked by hand | Breaking schema changes are split across releases, and contract steps must be tracked so they are not forgotten. `migrate:down` is for development; in production the way back is a new forward migration.                                               | [ADR-0020](adr/0020-expand-then-contract-migrations.md#negative--costs)                                                                                                                                                             |

## Next three things to build

These are recommendations, not decisions. Each is a follow-up the repository's own documents already name, in the order below. Each would start, as every change does here, with a spec change for the owner to approve ([AGENTS.md section 2](../AGENTS.md#2-workflow-spec-first)).

| Order | What                              | Why, in the source's words                                                                                                                                                                                                                                                                                                            | Source                                                                                                                                                                                                                                                                                     |
| ----: | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
|     1 | A one-off reconcile task in AWS   | The only item `docs/deployment/aws.md` lists as a follow-up: a task on the tools stage, run like the migration task, in the tasks' security group. The reconciliation is how the service proves no money was created, destroyed or misplaced, and the ADRs list its result as a thing to monitor.                                     | [AWS limitations](deployment/aws.md#limitations-and-follow-ups), [ADR-0006](adr/0006-double-entry-ledger-with-signed-integer-minor-units.md#positive), [ADR-0005](adr/0005-postgresql-as-the-only-source-of-truth.md#to-monitor)                                                           |
|     2 | Prometheus metrics scraped in AWS | Named "the next step": an AWS Distro for OpenTelemetry collector as a sidecar, writing to Amazon Managed Service for Prometheus, with Amazon Managed Grafana. The "To monitor" lists of the ADRs name the service's own metrics, such as `scf_lock_timeouts_total` and `scf_db_pool_connections`, which nothing scrapes in AWS today. | [AWS observability](deployment/aws.md#observability), [spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope), [ADR-0023](adr/0023-optional-observability-off-by-default.md#follow-ups), [ADR-0008](adr/0008-read-committed-with-ordered-pessimistic-row-locks.md#to-monitor) |
|     3 | Error reporting in AWS            | Needs a NAT gateway with an egress allow-list for the endpoint, and the DSN as a Secrets Manager secret. ADR-0016 treats every 500 in production as a defect, and the reporter groups them with their correlation id.                                                                                                                 | [Spec 008 section 6](../specs/008-deployment/spec.md#6-out-of-scope), [ADR-0023](adr/0023-optional-observability-off-by-default.md#follow-ups), [ADR-0016](adr/0016-error-model.md#to-monitor)                                                                                             |

Further follow-ups the ADRs record with a trigger rather than an order: a new ADR for an identity provider, JWKS caching and the (issuer, subject) mapping table once a provider is chosen ([ADR-0012](adr/0012-simulated-authentication-with-jwt-and-two-roles.md#follow-ups)); two-phase idempotency keys once the service calls an external system ([ADR-0009](adr/0009-idempotency-inside-the-movements-transaction.md#negative--costs)); and a new ADR on the foreign key or balance snapshots if multixacts become a problem ([ADR-0007](adr/0007-system-accounts-without-a-cached-balance.md#follow-ups)).
